# Module & Infrastructure Map

> **Read this before building anything new.** This is the "what already exists and where"
> index for TrainingAI. Its job is to stop the recurring failure where a new feature
> re-implements infrastructure that already exists — the way a GitHub Actions cron was
> nearly added when the app already has a throttled-write-path pattern for exactly that
> (see [Recurring / scheduled / background work](#0-recurring--scheduled--background-work-read-this-first)).
>
> This enforces the **One Formula, One Place** rule from `CLAUDE.md` at the module level:
> before writing a helper, a fetch path, a scheduled job, a validation schema, a date
> calc, a cache key, or a UI primitive, **grep this file first**, then grep the codebase
> for the symbol. If it exists, import it. If it half-exists, extend it in place.
>
> **Keeping it current:** when you add a genuinely new piece of shared infrastructure
> (a new `lib/` domain, a cross-cutting helper, a new provider, a new scheduled-work
> pattern), add a one-line row here in the same PR. This is a map, not an exhaustive
> API listing — link to the file and let the reader open it. If a row here is wrong,
> the file wins; fix the row.

> **Reading a PR number in these docs.** This repository begins at one commit — the 2026-08-16
> snapshot of a private repo that had reached ~#1399. Every PR number cited below roughly **#1250 and
> under refers to that archived repository**, `nekodas-neko/TrainingAI`, not to a pull request here,
> and the numbering restarts from #1 in this one. The archived repo is read-only rather than deleted
> precisely so those references stay resolvable. See [`NOTICE`](../NOTICE) for why the history could
> not come across.

## 0. Recurring / scheduled / background work — READ THIS FIRST

**There is no cron layer, no job queue, and no GitHub Actions schedule in this app.**
`.github/workflows/ci.yml` is CI-only (lint/typecheck/test/build on PR + push to `main`).
This is deliberate — it is a single-user PWA on Railway, and it drives "recurring" work
through four existing patterns. **Before adding any scheduler, pick one of these:**

| Pattern | What it's for | Where it lives | Reference example |

Needed in three places: after Q-541's packing backfill, after migration 193's index drop, and on `error_events` (4 live rows in 49 MB). Takes an ACCESS EXCLUSIVE lock and needs free disk equal to the table's current size |
| **Oura VACUUM FULL / disk reclaim (culling Lever 1c)** | Physically shrink `oura_raw_samples` after Lever 1b — nulling `decoded` only frees space logically (MVCC dead tuples; the file never shrinks without a rewrite). | **Repository "not found" → HTTP status** | Answer "the row you named does not exist / is not yours" with a status instead of a 500 | `packages/shared/src/errors.ts` → `NotFoundError` / `isNotFoundError`; `lib/api/route-errors.ts` → `routeErrorResponse(err)` (maps or re-throws) and `withRouteErrors(fn)` (for routes with no catch) | **Throw the typed error in the repository; map it once at the boundary.** Sixteen bare `throw new Error('… not found')` used to reach Next's default handler as 500 with an empty body, which told the sync path to retry what can never succeed. `isNotFoundError` checks a **marker property, not `instanceof`** — the Next bundle and the rollup worker's esbuild output hold separate copies of the class. The mapper **re-throws** anything else, so a genuine bug still reaches `error_events`. ⚠️ Do **not** apply this to a DELETE of an absent row — idempotent, the end state holds, and seven of them correctly answer 200 |
| **Session duration — bounded, and the bound is shared** | A workout session's wall-clock span is only usable below `MAX_PLAUSIBLE_SESSION_MIN` (240). | **Oura raw-frame reads — ALWAYS two-tier** | Raw BLE frames live in `oura_raw_samples` (the 7-day hot window) *and* `oura_raw_packed` (sealed per-bucket blobs, Q-541). **Never query either table directly for frames** — a hot-only read silently returns a 7-day history and looks exactly like data loss | `lib/data/postgres/slices/oura-raw-frames.ts` → `readRawFrames(db, userId, {tags?, startDs?, endDs?})` (ascending) and `readRecentRawFrames(db, userId, tags, limit)` (newest-first, cold only if hot comes up short); the codec is `lib/oura-ble/frame-pack.ts` → `packFrames`/`unpackFrames`/`hexToBody`/`bodyToHex` | Both return the exact shape of the `select` they replaced (`ds`, `tag`, `bodyHex`, `decoded`). Overlap is deduped on the ingest unique key `(ds, tag, body_hex)`, because the packer writes-verifies-then-deletes and a bucket is legitimately in both tiers meanwhile. **An aggregate cannot use that dedupe** — count via an anti-join on `(epoch, tag, ds_bucket)` instead, as `getOuraRawSampleSummary` does; summing the tiers double-counts. `event_name` and `measured_at` are derived (`eventName(tag)`, `resolveDsToMs`), never read — a packed frame carries neither |
| **Oura frame packer (Q-541 Task 4) — the ONLY delete of an archival frame** | Move a sealed bucket of raw frames out of `oura_raw_samples` into one blob in `oura_raw_packed`. Bounded, idempotent, resumable; **runs automatically from the ingest path** (Task 6) and on the admin button | `lib/data/postgres/slices/oura-raw-pack.ts` → `packOuraRawBuckets(db, userId, maxBuckets)` / `countPackableBuckets` / `verifyStoredBucket` / `frameSequenceSha256`; `GET\|POST /api/oura-ble/samples/pack` (admin-gated, POST 10/min) | Three phases, deliberately NOT one transaction: seal → insert + **re-read from the DB and prove equal** → delete. A bucket is sealed only when its ds is below `max(ring_timestamp_ds) - HOT_WINDOW_DS` **and** `max(recorded_at) < now() - 1 day` — ds says when the ring *recorded* a frame, not when we received it, so a re-drain would otherwise look eligible. `body_sha256` hashes the frame *sequence*, not the blob, so it is an independent check. `ON CONFLICT DO NOTHING`, never `DO UPDATE`. A refused bucket is returned, not thrown — and on an automatic run it is also written to `error_events`, because there is no caller to hand it to. The automatic run is throttled **per user** (`claimAutoPackSlot`, 6 h, `AUTOPACK_MAX_BUCKETS` 8) — one shared timestamp lets a busy user starve another's table — and `OURA_AUTOPACK=off` disables it without a code deploy. Phase 3 deletes **by row id**, never by the bucket's ds range: a frame arriving between the select and the delete would otherwise be removed having never been packed |
| **Ring clock epochs — a re-key is DECLARED, never inferred (Q-314)** | Decide whether a ds regression means the ring's clock restarted or that it is replaying history it already sent. Getting this wrong re-times the entire sleep history | `lib/oura-ble/clock.ts` → `classifyClockRegression(batchMaxDs, epochMaxDs, rekeyDeclared)` (the decision), `isCounterRestart` + `EPOCH_RESTART_RATIO` (the net), `isClockEpochReset` (regression only, says nothing about why); `declareOuraRekey`/`getPendingRekeyDeclaration`/`consumeRekeyDeclaration`/`cancelPendingRekeyDeclaration` in `slices/oura.ts`; `GET\|POST\|DELETE /api/oura-ble/rekey` | **A regression alone is NOT evidence of a reset** — a re-drain produces one, and reading it as a reset cost +12.17 h and +14.16 h of history re-timing. A declaration is consumed by the NEXT ingest batch (the new ds is unknowable before then) and only after its anchor is written. `EPOCH_RESTART_RATIO = 0.05` is a *net* for an undeclared re-key, validated only against the two re-drains it must not fire on — there is no observed true reset in the data |

Do not add a new reader of either column: derive from the anchors and from `tag` |

| **App-open / resume throttled sync** | "Pull fresh external data when the user opens the app," ≤ once per window | **Nothing — there is no such mechanism any more.** | Its one instance was the Oura Cloud sync on mount + native `resume` (≤1×/6h, `OURA_LAST_SYNC_KEY`), removed with the Cloud integration on 2026-08-13 (Q-224). `lib/oura/sync-throttle.ts` is deleted. The hazard is a second request arriving before the first lands: `cachedFetch` revalidates on every screen open, so a route reached from the app is hit repeatedly within seconds | `packages/shared/src/ai-periodization/regenerate-in-background.ts` → `regeneratePrescriptionInBackground(userId, sessionId, {today, allow, run, onError})` — one marker per `(user, session, local day)`, taken before the work and released when it settles | A rate limit is a counter over a window and cannot tell "already running" from "ran a minute ago" — Q-535 says the same of its 4/min. **Release on rejection too**, or a failed run wedges that key until restart. **Check the guard before the limit**, so a deduped call spends no budget. ## 1. Dates & timezones — `packages/shared/src/date-utils.ts`

**The app is AEST (`Australia/Brisbane`, `DEFAULT_TZ`). Never `new Date().toISOString().slice(0,10)`.**
See the full timezone rules in `CLAUDE.md`.

| Need | Use |
|---|---|
| Today as `YYYY-MM-DD` in user tz | `todayInTz(tz?)` |
| Day-of-week (0–6) in tz | `todayDayOfWeek(tz?)` |
| Start of week | `startOfWeekInTz(tz?)` |
| Local midnight `Date` (overflow-safe) | `aestMidnight(y, m, d, tz?)`, `todayMidnightUtc(tz?)` |
| Shift a date string by N days | `shiftDateStr(dateStr, days)` |
| Workout kcal from heart rate | `estWorkoutKcalFromHr` (`packages/shared/src/health/workout-energy.ts`) — Keytel et al. 2005, kJ/min → kcal, floored at 0, `null` outside `[HR_MIN_PLAUSIBLE, HR_MAX_PLAUSIBLE]` or on an incomplete profile (Q-421). `computeActiveEnergy` prefers it per session and falls back to the MET tier, which was always Oura's `has_enough_motion === false` branch. `avg_bpm` batch-read via `getAvgBpmBySession`. |
| Per-session workout kcal | `computeActiveEnergy` (`packages/shared/src/health/daily-energy.ts`) returns `workoutKcalBySession: { id, kcal }[]` — the exact addends of the day's `workoutKcal`, surfaced on `/api/nutrition/energy-balance` under `activeBreakdown` (Q-391). Join on `workoutSessionId` from `/api/day-log`. **Do not compute a second per-session estimate elsewhere** — the day screen's Energy total reads this same route precisely so the two cannot disagree. Unrounded; round at render. |
| Client "today" in the user's zone | `useUserTimezone()` (`components/shell/user-timezone-provider.tsx`) → `todayInTz(tz)`. | Is a date-**shaped** string a real day? | `isCalendarDate(dateStr)` — the shape regexes accept `2026-13-45`, `2026-02-31`, `0000-00-00`, which then fail at the driver as `[pg 22008]`: a client input error filed as a server fault (Q-496). Both separators. Used by `MutationSchema.date` and `resolveIngestDate`. |
