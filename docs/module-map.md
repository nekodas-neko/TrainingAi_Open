# Module & Infrastructure Map

> **Read this before building anything new.** This is the "what already exists and where"
> index for TrainingAI. Its job is to stop the recurring failure where a new feature
> re-implements infrastructure that already exists — the way a GitHub Actions cron was
> nearly added when the app already has a throttled-write-path pattern for exactly that
> (see [Recurring / scheduled / background work](#0-recurring--scheduled--background-work-read-this-first)).
>
> This enforces the **One Formula, One Place** rule from `CLAUDE.md` at the module level:
> before writing a helper, a fetch path, a scheduled job, a validation schema, a date
> calc, a cache key, or a UI primitive, **grep this file first**, then grep the codebase
> for the symbol. If it exists, import it. If it half-exists, extend it in place.
>
> **Keeping it current:** when you add a genuinely new piece of shared infrastructure
> (a new `lib/` domain, a cross-cutting helper, a new provider, a new scheduled-work
> pattern), add a one-line row here in the same PR. This is a map, not an exhaustive
> API listing — link to the file and let the reader open it. If a row here is wrong,
> the file wins; fix the row.

> **Reading a PR number in these docs.** This repository begins at one commit — the 2026-08-16
> snapshot of a private repo that had reached ~#1399. Every PR number cited below roughly **#1250 and
> under refers to that archived repository**, `nekodas-neko/TrainingAI`, not to a pull request here,
> and the numbering restarts from #1 in this one. The archived repo is read-only rather than deleted
> precisely so those references stay resolvable. See [`NOTICE`](../NOTICE) for why the history could
> not come across.

## 0. Recurring / scheduled / background work — READ THIS FIRST

**There is no cron layer, no job queue, and no GitHub Actions schedule in this app.**
`.github/workflows/ci.yml` is CI-only (lint/typecheck/test/build on PR + push to `main`).
This is deliberate — it is a single-user PWA on Railway, and it drives "recurring" work
through four existing patterns. **Before adding any scheduler, pick one of these:**

| Pattern | What it's for | Where it lives | Reference example |
|---|---|---|---|
| **Opportunistic throttled prune from a write path** | Server-side periodic maintenance (retention, cleanup) — fire *after* a write, at most once per window | `lib/data/postgres/retention-throttle.ts` → `shouldPrune(lastPruneMs, nowMs, windowMs)` | Prunes (all ≤1×/24h, throttled + fire-and-forget with a logged `.catch`): 180-day `oura_heartrate` (after HR insert), **90-day `rr_intervals`** (migration 124, after `insertRrIntervals` — review H-1/Lever R; safe because `workout_hr_stats` snapshots the workout-HRV scalar), 30-day `error_events`, **30-day `step_live_windows`** (after `upsertStepLiveWindow` — Sub-plan A Lever 3), 7-day `oura_accel_chunks` (after accel-chunk insert), **90-day `oura_ble_battery_poll`** (migration 133, after battery-poll insert) |
| **Oura raw-storage tag whitelist (culling Lever 2)** | Drop pure-telemetry/debug BLE tags at ingest so they never hit `oura_raw_samples` (forward-only, reversible) | `lib/oura-ble/raw-storage.ts` → `RAW_STORAGE_DROP_TAGS`/`shouldDropRawTag(tag)`, applied in `POST /api/oura-ble/samples` | Drops `0x42/0x43/0x45/0x53/0x56/0x5b/0x61/0x79/0x82/0x83`; the rollup-consumed set (incl. `0x7e/0x7f` gait features) is `ROLLUP_CONSUMED_TAGS` in `lib/oura-ble/rollup-consumed-tags.ts` — the raw-storage test imports it and asserts the two sets never intersect (single source, can't drift — review G-1). 0x61 stays dropped except its battery subtypes (`isBatteryDebugEvent`) |
| **Oura `decoded`-JSONB drop / decode-from-hex (culling Lever 1)** | Stop persisting the re-derivable `decoded` column (≈halves `oura_raw_samples` row cost); decode from archival `body_hex` in-memory instead (forward-only, non-destructive) | `insertOuraRawSamples` writes `decoded = NULL`; `aggregateOuraRawSamples`'s `rowsByTags` + `getOuraRawSampleSummary`/`getOuraRawSamplesByTags` coalesce `decoded ?? decodeEventBody(tag, hexToBytes(body_hex))` (all in `lib/data/postgres/adapter.ts`) | Historical rows with a stored `decoded` still work (coalesce); `redecodeOuraRawSamples` no longer re-persists `decoded`. Nulling historical rows (Lever 1b) + `body_hex` retention (Lever 5) are separate data-dropping steps, confirm-first |
| **Oura historical-`decoded` backfill (culling Lever 1b, data-dropping)** | Bulk-null `decoded` on rows written before Lever 1a shipped, admin-triggered only (never auto-runs) | `lib/data/postgres/slices/oura.ts` → `nullHistoricalDecoded(db, userId, maxRows)` — bounded 500-row batches, capped/call, idempotent/resumable; `POST /api/oura-ble/samples/backfill-null-decoded` (admin-gated); confirm-dialog-gated button in the admin console's ① Data section (`DbFootprintCard`) | `body_hex` never touched. Watch `decodedRows`/`decodedBytes` via `getOuraStorageStats` (G-2) to confirm progress; press again until `remaining` is 0 |
| **Disk reclaim — `VACUUM FULL` on an allowlisted table (Q-315)** | Return space to the OS after rows are deleted or an index is dropped. MVCC frees dead tuples logically; only a rewrite shrinks the file | `lib/data/postgres/slices/oura.ts` → `vacuumTableFull(table)` + `VACUUM_FULL_TABLES` (the allowlist); `GET\|POST /api/admin/vacuum` (admin-gated, 4/min). `vacuumOuraRawSamples()` and its own route are the original single-table entry point, unchanged | **The table name is interpolated into the statement — VACUUM takes no bind parameter — so the allowlist IS the safety boundary.** Checked with `hasOwnProperty`, not `in` (`'toString' in obj` is true for every object); mutation-checked test. Needed in three places: after Q-541's packing backfill, after migration 193's index drop, and on `error_events` (4 live rows in 49 MB). Takes an ACCESS EXCLUSIVE lock and needs free disk equal to the table's current size |
| **Oura VACUUM FULL / disk reclaim (culling Lever 1c)** | Physically shrink `oura_raw_samples` after Lever 1b — nulling `decoded` only frees space logically (MVCC dead tuples; the file never shrinks without a rewrite). Admin-triggered only, brief `ACCESS EXCLUSIVE` lock | `lib/data/postgres/slices/oura.ts` → `vacuumOuraRawSamples()` (dedicated pool connection, `SET statement_timeout=0`, `VACUUM (FULL) oura_raw_samples`, `release(true)`); `POST /api/oura-ble/samples/vacuum` (admin-gated, 2/min); button in `DbFootprintCard` ① Data section | No data dropped (`body_hex` + all rows preserved); returns before/after/reclaimed bytes. Never auto-run — owner presses it, watching G-2 |
| **Repository "not found" → HTTP status** | Answer "the row you named does not exist / is not yours" with a status instead of a 500 | `packages/shared/src/errors.ts` → `NotFoundError` / `isNotFoundError`; `lib/api/route-errors.ts` → `routeErrorResponse(err)` (maps or re-throws) and `withRouteErrors(fn)` (for routes with no catch) | **Throw the typed error in the repository; map it once at the boundary.** Sixteen bare `throw new Error('… not found')` used to reach Next's default handler as 500 with an empty body, which told the sync path to retry what can never succeed. `isNotFoundError` checks a **marker property, not `instanceof`** — the Next bundle and the rollup worker's esbuild output hold separate copies of the class. There is deliberately **no not-owned status**: 404 for both, or the write surface becomes a membership oracle. The mapper **re-throws** anything else, so a genuine bug still reaches `error_events`. ⚠️ Do **not** apply this to a DELETE of an absent row — idempotent, the end state holds, and seven of them correctly answer 200 |
| **Oura raw-frame reads — ALWAYS two-tier** | Raw BLE frames live in `oura_raw_samples` (the 7-day hot window) *and* `oura_raw_packed` (sealed per-bucket blobs, Q-541). **Never query either table directly for frames** — a hot-only read silently returns a 7-day history and looks exactly like data loss | `lib/data/postgres/slices/oura-raw-frames.ts` → `readRawFrames(db, userId, {tags?, startDs?, endDs?})` (ascending) and `readRecentRawFrames(db, userId, tags, limit)` (newest-first, cold only if hot comes up short); the codec is `lib/oura-ble/frame-pack.ts` → `packFrames`/`unpackFrames`/`hexToBody`/`bodyToHex` | Both return the exact shape of the `select` they replaced (`ds`, `tag`, `bodyHex`, `decoded`). Overlap is deduped on the ingest unique key `(ds, tag, body_hex)`, because the packer writes-verifies-then-deletes and a bucket is legitimately in both tiers meanwhile. **An aggregate cannot use that dedupe** — count via an anti-join on `(epoch, tag, ds_bucket)` instead, as `getOuraRawSampleSummary` does; summing the tiers double-counts. `event_name` and `measured_at` are derived (`eventName(tag)`, `resolveDsToMs`), never read — a packed frame carries neither |
| **Oura frame packer (Q-541 Task 4) — the ONLY delete of an archival frame** | Move a sealed bucket of raw frames out of `oura_raw_samples` into one blob in `oura_raw_packed`. Bounded, idempotent, resumable, admin-triggered; **never automatic on deploy** | `lib/data/postgres/slices/oura-raw-pack.ts` → `packOuraRawBuckets(db, userId, maxBuckets)` / `countPackableBuckets` / `verifyStoredBucket` / `frameSequenceSha256`; `GET\|POST /api/oura-ble/samples/pack` (admin-gated, POST 10/min) | Three phases, deliberately NOT one transaction: seal → insert + **re-read from the DB and prove equal** → delete. A bucket is sealed only when its ds is below `max(ring_timestamp_ds) - HOT_WINDOW_DS` **and** `max(recorded_at) < now() - 1 day` — ds says when the ring *recorded* a frame, not when we received it, so a re-drain would otherwise look eligible. `body_sha256` hashes the frame *sequence*, not the blob, so it is an independent check. `ON CONFLICT DO NOTHING`, never `DO UPDATE`. A refused bucket is returned, not thrown |
| **Ring clock epochs — a re-key is DECLARED, never inferred (Q-314)** | Decide whether a ds regression means the ring's clock restarted or that it is replaying history it already sent. Getting this wrong re-times the entire sleep history | `lib/oura-ble/clock.ts` → `classifyClockRegression(batchMaxDs, epochMaxDs, rekeyDeclared)` (the decision), `isCounterRestart` + `EPOCH_RESTART_RATIO` (the net), `isClockEpochReset` (regression only, says nothing about why); `declareOuraRekey`/`getPendingRekeyDeclaration`/`consumeRekeyDeclaration`/`cancelPendingRekeyDeclaration` in `slices/oura.ts`; `GET\|POST\|DELETE /api/oura-ble/rekey` | **A regression alone is NOT evidence of a reset** — a re-drain produces one, and reading it as a reset cost +12.17 h and +14.16 h of history re-timing. A declaration is consumed by the NEXT ingest batch (the new ds is unknowable before then) and only after its anchor is written. `EPOCH_RESTART_RATIO = 0.05` is a *net* for an undeclared re-key, validated only against the two re-drains it must not fire on — there is no observed true reset in the data |
| **Oura wall-clock reads over raw frames — derive, never read a stored stamp** | Answer "which frames in the last N days" and "when did the ring last report" without touching the `measured_at` column, which is dead | `getOuraRawSamplesForTags` (`adapter.ts`) converts the window via `resolveMsToDs` then reads `readRawFrames`; `getLatestOuraBleMeasuredAt` (`slices/oura.ts`) takes `max(ring_timestamp_ds)` across both tiers and resolves it; `hasOuraBleSamples` answers *existence* (what `connected` actually means) | Migration 193 dropped `idx_oura_raw_samples_user_measured` (136 MB) once these were the only readers. `oura_raw_samples.measured_at` and `event_name` are **dead columns** — still present, written at ingest, read by nothing; the redecode's re-stamp of them is a documented no-op, and it was the mechanism of the 2026-08-17 disk_full outage. Do not add a new reader of either column: derive from the anchors and from `tag` |
| **Oura DB-footprint readout (culling G-2)** | Per-table row/byte estimates + an exact `decoded`-vs-`body_hex` split on `oura_raw_samples`, so culling levers are sized from real numbers | `lib/data/postgres/slices/oura.ts` → `getOuraStorageStats(db)` (`pg_stat_user_tables` for cheap per-table stats + one exact scan for the raw-sample column split); `GET /api/oura-ble/db-stats` (admin-gated); `DbFootprintCard` in the ① Data section, lazy-fetched on section expand | Read-only |
| **App-open / resume throttled sync** | "Pull fresh external data when the user opens the app," ≤ once per window | **Nothing — there is no such mechanism any more.** | Its one instance was the Oura Cloud sync on mount + native `resume` (≤1×/6h, `OURA_LAST_SYNC_KEY`), removed with the Cloud integration on 2026-08-13 (Q-224). `lib/oura/sync-throttle.ts` is deleted. If a future feature needs an app-open throttle, write it fresh rather than restoring that one — and note that `lib/oura/ble-freshness.ts` → `isBleDataFresh(...)` survives, as the "does the ring have recent data" question, no longer as a gate on a Cloud call. |
| **Client-scheduled local notifications** | User-facing reminders at a wall-clock time | `lib/notifications.ts`, `lib/meal-reminders.ts`, `lib/workout-reminders.ts`, `lib/supplement-reminders.ts` — all `reconcileX`/`computeXAction` + Capacitor `LocalNotifications` | Meal / workout / supplement / rest-complete reminders, reconciled in `sync-provider.tsx` |
| **Long admin operations — return a job id, do not hold the request (Q-535)** | An admin action whose work outlasts the gateway timeout. The only instance is the full redecode; the 502 it produced was read as a failure for work that had completed, which invited a retry of the heaviest pair of calls in the app | `POST /api/oura-ble/samples/redecode?async=1` → `{jobId, status, startedAt, alreadyRunning}`, `GET …?jobId=…` polls · store in `slices/oura.ts` → `startRedecodeJob` / `getRedecodeJob` / `getLatestRedecodeJob` / `finishRedecodeJob` / `reapStaleRedecodeJobs` · table `oura_redecode_jobs` (migration 196) | `status` is DERIVED from the timestamps, never stored, so nothing can disagree with them. One in-flight job per user on a partial unique index — a rate limit does not prevent overlap. **A staleness reaper is not optional**: a process that dies mid-run otherwise holds that slot forever and refuses every future run. State is in a table, not memory, so a restart cannot silently lose a job. `?async=1` is opt-in until Q-318 lands the client poller |
| **Off-loop CPU work — a `worker_threads` worker** | Server-side work heavy enough to stall the request loop. **The only instance is the BLE rollup** (Q-213 Stage 2) — do not add a second without reading why this one exists | `lib/oura-ble/rollup-worker.ts` → `runRollupOffLoop(...)` / `runRedecodeOffLoop(...)` (main-thread client: lazy singleton worker, restarts on exit, **falls back to in-process** if the bundle is missing) · the ingest route's coalescing is `lib/oura-ble/rollup-debounce.ts` → `createRollupDebouncer` (trailing-edge debounce + max-wait, injected clock/timer) · `lib/oura-ble/rollup-worker-entry.ts` (worker side) · `scripts/build-rollup-worker.mjs` → `.rollup-worker/rollup-worker.cjs`, built by `pnpm build` and `pnpm dev` | It needs its own esbuild bundle because the repository reaches `onnxruntime-node`, which webpack cannot bundle (`serverExternalPackages`), so there is no Next output to point a `Worker` at. The worker runs the same `lib/data/postgres/client.ts` in its own realm, so it sets `PG_POOL_MAX=2` — `poolMax()` can only ever *lower* the 10 |
| **Cold-start schema apply** | Run DB work once per deploy/boot | `ensureSchema` (Postgres migrations) / `MIGRATIONS` (`lib/sqlite/migrations.ts`) applied on first DB open | Migrations auto-apply on cold start — no migration runner job needed |

`retention-throttle.ts`'s own header comment says it plainly: *"never a scheduled job,
since this app has no cron layer."* If you think you need a real scheduler, that's a
design decision to raise with the user first — don't add one silently.

Server push (not scheduled — triggered by events): `lib/push.ts` (`sendPushToUser`),
client subscription in `lib/push-client.ts`, VAPID-gated.

## 1. Dates & timezones — `lib/date-utils.ts`

**The app is AEST (`Australia/Brisbane`, `DEFAULT_TZ`). Never `new Date().toISOString().slice(0,10)`.**
See the full timezone rules in `CLAUDE.md`.

| Need | Use |
|---|---|
| Today as `YYYY-MM-DD` in user tz | `todayInTz(tz?)` |
| Day-of-week (0–6) in tz | `todayDayOfWeek(tz?)` |
| Start of week | `startOfWeekInTz(tz?)` |
| Local midnight `Date` (overflow-safe) | `aestMidnight(y, m, d, tz?)`, `todayMidnightUtc(tz?)` |
| Shift a date string by N days | `shiftDateStr(dateStr, days)` |
| Format a `Date`/ms to tz day/string | `toAestDay`, `toAestDateStr`, `fmtAest(ms, tz?)`, `formatTime12h(hhmm)` |
| A clock time that gets **persisted** (`activity_logs.start_time`) | `msToHHMMInTz(at, tz?)` — never `d.getHours()`, which stores the phone's clock rather than the user's wall time. Replaced four private copies of the same helper. |
| In an API route, from the session | `session.user.timezone ?? DEFAULT_TZ`, then `formatInTimeZone(...)` from `date-fns-tz` |

Range/window math beyond "today" also lives here — do not hand-add to calendar
components (`CLAUDE.md` "Date Arithmetic" section).

## 2. Client cache (SQLite-backed) — `lib/sqlite/cache.ts`, `lib/cache-groups.ts`, `lib/cache-ttl.ts`

Client GETs of `/api/*` go through this, never bare `fetch`. See the strict
cache-invalidation rules in `CLAUDE.md`.

| Concern | Use |
|---|---|
| Fetch + cache (background revalidate) | `cachedFetch<T>(key, url, ttl)`; today-scoped: `cachedFetchToday` |
| Synchronous seed for instant paint | `readCacheSync<T>(key)`, `readTodayCacheSync<T>(key)` |
| Direct read/write/update | `getCached`, `setCached`, `updateCache` |
| Invalidate after a write | **A named group in `lib/cache-groups.ts`** — never a hand-rolled key list |
| Sign out | **`signOutAndClearDevice()` in `lib/sign-out.ts`** — the only sign-out path. Wipes the local store and the cache before the server action; a `<form action={signOut}>` cannot run either clear. CI-enforced by `check-sign-out-clears-device.js` (Q-172) |
| Bypass the browser HTTP cache | Already done, twice over. Client side: `cachedFetch` sends `cache: 'no-store'` and so does the service worker's `/api/` branch — a new fetch helper needs the same bypass (2026-08-09). Server side: every `app/api` response is `Cache-Control: private, no-store`, enforced by `check-api-no-store.js` (Q-166, 2026-08-10) — **do not add `max-age`/`stale-while-revalidate` to a route**; that layer is under this one and `invalidateCache()` cannot reach it |
| TTL for a key | A named constant in `lib/cache-ttl.ts` (`TTL_SHORT/MEDIUM/LONG` + per-key) |
| Warm list on app open | `CACHE_TASKS` in `components/sync-provider.tsx` |
| Offline seed floor (localStorage survives a fully-offline device) | `floorSeedTtl()`/`OFFLINE_SEED_TTL_FLOOR` (7d) in `lib/cache-ttl.ts`, applied in `setCached`'s localStorage write — does not affect the SQLite `api_cache` layer's real TTL |

**Cache groups** (call after the matching write): `invalidateWorkoutSummaries`,
`invalidateReadinessInputs`, `invalidateProgramStructure`, `invalidateBiometrics`,
`invalidateGoalRecommendations`, `invalidateOuraSync`, `invalidateInjuryWrites`,
`invalidateActivityWrites`, `invalidateBodyMetricWrite`, `invalidateFriends`,
`invalidateSupplements`, `invalidateHealthTrends`, `invalidateNutritionWrite`,
`invalidateExerciseLogged`, `invalidateMealTypes`, `invalidateUserProfile`,
`invalidateOuraToken`, `invalidateAiPeriodization`, `invalidateExerciseLibrary`,
`invalidateActivityTypes`. `invalidateWorkoutSummaries`/`invalidateProgramStructure` both
call the shared `clearLegacyHomeSeeds()` (sessionStorage `ta_recommendation_v1`/`ta_meta_v1`)

**BLE drain settling → client cache bust:** `syncOuraRing()` (`lib/oura-ble/sync.ts`) polls the
plugin's `draining` status flag after kicking a drain/start, then calls `invalidateOuraSync()`
and dispatches a `window` event `ta:oura-ble-synced` once settled — home

off-device or without the plugin.

Records `urlMs` / `paintMs` / `settleMs` per tap plus `rscCount` — **`rscCount === 0` means the route was prefetched**, which is the direct read-out on whether a `router.prefetch` is working. Do not hook `usePathname` for this: `/workout` → `/workout?session=…` changes only the query and would be missed |
| Server errors that escape a route | `onRequestError` in `instrumentation.ts` → `lib/observability/request-error.ts` → `error_events`. Covers the 80 route files with **no** `catch`. **Does NOT see a route that catches its own error and returns a 500** — those need `reportServerError` (`lib/observability.ts`) in the catch block. Deduped 60 s per route+message — on the **base** message, before the pg-code prefix is added, so a cause that varies between identical failures can't defeat the window; the DB volume is the binding constraint. Talks to the `pg` pool directly, never the repository — the adapter pulls onnxruntime-node, which webpack can't bundle from instrumentation |
| Lifting the real Postgres error out of a Drizzle wrapper | `lib/observability/pg-cause.ts` → `summariseCause()`. **Imports nothing**, deliberately: `request-error.ts` runs from an instrumentation entry point and so can never import `lib/observability.ts` (adapter → onnxruntime-node). Both error paths call it, so there is one implementation rather than a copy on each side. Puts the pg `code` in a message **prefix**, because the standing session-start query groups by `left(message,120)` and a `Failed query:` message runs past that — a suffix is invisible in exactly the read that matters |
| Running the actual app in a test (E2E) | `playwright.config.ts` + `e2e/` (Q-249) — `pnpm e2e`, its own `E2E` CI job, **not** a required check yet. `e2e/auth.setup.ts` signs in through the real form once and saves `storageState`; `e2e/fixtures.ts` holds `visitTwice` / `settleRouteBoundary` / `expectNoSkeleton`. **Read `e2e/README.md` before trusting a green run** — it drives the **web** build (`getLocalStore` is null, so the device branch never runs), uses `pnpm dev` because the pg pool forces SSL under `NODE_ENV=production`, and counts skeletons **in the viewport only**, so a tabbed screen like Health is one panel covered. `vitest.config.ts` excludes `e2e/**`; without that, vitest collects the specs and reports "1 failed file, 0 failed tests" |
| Runbooks | `docs/runbooks/` |
