## Lessons that cost real time

- **AN ENTRY'S SUGGESTIONS AND ITS DIAGNOSIS ARE BOTH HYPOTHESES.** RV-219 ② offered "wrap the name OR shrink the icons" — the icons are `h-12 w-12`, the 48 px Android tap-target floor, so that option trades a naming problem for an accessibility one; the guard pins the size beside the wrap, since only the wrap is obvious later. And a missed-convention shape has an opposite that looks identical: sweep 64 blamed RV-214 ① on the icon map's fallback (the surface never called the map), while RV-219 ①'s `0kg` CANNOT call `isBodyweightType` — `DayExercise` carries no `exerciseType` and every consumer takes it as a prop. **Check what the render site is GIVEN before filing a skipped helper.** (Also: re-applying this baton across merges re-added two lessons verbatim — grep your own headlines before adding.)
- **VERIFY EACH SWEEP ITEM AGAINST `main` AS YOU TAKE IT, AND PIN PROPERTIES NOT STRINGS.** RV-218's third copy bug was already fixed by RV-208 (#1743) hours earlier in the same file — sweep findings are snapshots. And `movement-breakdown.test.ts` failed on the CORRECT fix because it asserted `"320 workouts · 227 steps"` exactly; a per-addend regex pinning the property (every addend carries its unit) guards the same thing without tripping on a right change.
- **LANE A vs B IS ANSWERED BY WHICH LAYER KNOWS THE FACT.** RV-218 ④ ("a 7-day chart draws 5 bars") looked like a chart bug; the route computes the window (`shiftDateStr(today, -6)`) and returns the aggregate verbatim, so the route is the only layer that knows there should be seven. Padding in the chart would make every future consumer re-derive the window.
- **A "N COMPONENTS DO X" COUNT IS A GREP, NOT A FINDING — CHECK ITS EXAMPLES FIRST.** RV-215 ② claimed 12 components vanish instead of saying why and named three; **all three were already correct** (one had `onError` plus an error line, two returned null ONLY while loading and then rendered an empty state). A `return null` while loading is a defer, not a vanish, and no line-level scan tells them apart. A minute on the named examples can void a whole item.
- **⚠ RE-GATING A RE-MERGE IN FULL CAN LIVELOCK — SIZE IT TO WHAT THE MERGE BROUGHT.** `main` takes a commit every ~8 min against a ~20 min full gate. A re-merge bringing only a peer's already-CI-green source plus version files gets `tsc` + `check:rules` + the doc checks, and CI runs the suite on the merged tree; one bringing source you DEPEND on gets the lot. State which in the PR body. **Resolve conflicts BEFORE any gate** — a gate on a conflicted tree fails on the markers and tells you nothing. **And `git diff --diff-filter=U` CANNOT confirm you resolved them: `git add -A` stages a conflicted file markers and all, after which the index reports zero.** It read 0 with `changelog.ts` still full of markers, which then got COMMITTED; `check:rules`' marker step caught it. The honest check is `grep -rl '^<<<<<<< HEAD'` over the tree.
- **THE VERSION LINE IS THE MOST RELIABLE CONFLICT HERE — EVERY LANE BUMPS IT.** #1775 burned three numbers as peers landed first. Rebuild `package.json`/`changelog.ts` from `origin/main`, never splice, and re-read main's version at the moment you push.
- **A COMMENT CLAIMING "EVERY OTHER SURFACE DOES X" IS NOT A GUARANTEE — GREP IT.** A-7's card comment said *"every other session surface uses getSessionIcon"*; **three did not**, and one printed `session.icon` as a 30 px WORD because the column is free text (RV-214 ①). When a comment asserts a convention, that is the moment to make it a check.
