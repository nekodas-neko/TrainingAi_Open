LA-136 — Home, sleep line

Home lost its sleep line, and the real signal is collected but unused

The old “Sleep: OK” was fabricated — a NOT NULL default on a field the check-in stopped collecting on 25 June, so it was the stored value on 93 of 108 rows. It was removed and nothing replaced it. Meanwhile the morning check-in does collect sleepQualityFeel, 1–5, with a touched flag, and nothing reads it.

The line comes back under the mood card, driven by what you actually answer each morning. The caption states whose number it is, so it can never be mistaken for a derived score again.

Not a one-line swap. Home sits in the persistent tab shell, so this read needs useCachedValue, a canonical TTL, and registration in every write group touching day_checkins — or it paints once and never refreshes, which is the bug class this repo has fixed twelve times.

RV-166 — Cardio hub, walk and run · revised

The prescription and the activity log are two different things

The first draft of this pane was wrong: it showed the prescription card replacing the modality picker, which lost Other and left no way to log a second activity. They are separate. The prescription is today's plan and there is one of it; the log is what you actually did and there can be any number, of any kind. Merging walk and run applies to the first only.

Where “Other” lives: exactly where it does now. The modality picker is untouched and always available — the prescription card sits above it, it does not replace it. My first draft dropped the picker from the after pane, which is what made this look like a problem.

How you do another: the same way as the first. The prescription is one item and is satisfied once; every activity after it is logged normally and appears under Logged today. The Plan chip marks the one that satisfied the prescription, so you can see which did at a glance.

One edge your rule leaves open, followed literally here. You said “one or the other”, so Run and Walk satisfy the prescription and Other does not — a 42-minute bike ride logs as Extra and leaves the run To do. That may be wrong for you: if a hard ride should count as having done your cardio, say so and Other gets a “count this as today’s cardio” action rather than a blanket rule.

Still true: this changes stored numbers, not just layout. Every past run day becomes completable, so adherence, streaks and compliance all move once it ships. Both panes here are rebuilt from cardio-content.tsx rather than screenshotted — the hub needs live data the sandbox lacks.

What I need from you: a yes, a no, or a change, for each of the four. They are independent — approving one does not commit you to the others.

Reversal cost is low on the first three: one component each, no stored data. RV-166 is the exception — it changes what counts as a completed session, so the numbers it moves are the part to think about.
