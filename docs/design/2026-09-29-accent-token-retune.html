Accent token retune

You answered this on 2026-09-26: retune the token to today’s #22c55e and #ef4444 first, then migrate the literal sites onto it — on the understanding that the app’s appearance would not change. I measured it before building. It changes a great deal.

The correction

The entry counted the literal sites and never counted the sites already using the token. Retuning the token repaints every one of those. It is the larger change of the two, not the neutral one.

Recommendation

Take (a) — migrate to the token

It gets the same one-source benefit for a fifteenth of the visual change, and it keeps the design system’s own values rather than overwriting them with copies that drifted. Every component written in the last several months already renders the bright token, so (a) is also the direction the app has been moving on its own.

  • (b) is still right if you prefer the mid green and red — that is a real preference and only you can hold it. It is worth knowing it is an app-wide restyle of roughly 212 readings, not a no-op, and that the brighter red is the one you see on every delete button.
  • (c) leave it loses the one-source benefit and keeps 116 literal sites drifting against the tokens. It also reverts a change already made in warmup-screen.tsx.
  • Reversal is cheap in effort either way — one token value, then a mechanical diff — but you have to look at a screen to judge it, which is the reason for this page.

One thing this page does not settle: amber. The difference is rgb(234,179,8) against rgb(239,175,0), which is below what the eye picks up on a phone, so it follows whichever option you take.
