## Recommended execution order

1. **Security** (plan 1) — N1 is a genuine cross-tenant write vulnerability; ship first.
2. **Caching** (plan 2) — highest user-visible correctness payoff (stale stats everywhere after a workout).
3. **Logic/correctness** (plan 5) — the PR-before-transaction data-integrity bug.
4. **Performance** (plan 3) — biggest mobile-feel win; the store-selector change is low-risk and high-impact.
5. **UI/consistency** (plan 4) — incremental polish, can be done piecemeal.

Each plan ends with its own verification + commit steps. After each plan lands, follow the CLAUDE.md end-of-session ritual: tick the roadmap, bump `package.json`, add a `lib/changelog.ts` entry if user-visible.

- Hardcoded session-name rule: `SESSION_TO_TAB` already removed; no live `"Push"/"Pull"/"Legs"` logic.
